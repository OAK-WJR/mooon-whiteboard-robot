## MCU and pins

The space review candidate changed to **ESP32-C6-MINI-1-N4 / C5736265**. In a conservative coarse-grid screening that kept the 19 through-hole contacts and the antenna keep-out, no position was found for the original WROOM; this is not a mathematical proof that it cannot be placed. The MINI trial placement fits in the existing board outline, but its global-site part number is **Standard Only, X-ray inspection required**, so the Economic assembly price cannot be reused. So this drawing is a space and wiring review candidate, and **has not become a low-cost final design**. [JLC part limits](https://jlcpcb.com/partdetail/ESPRESSIFINC-ESP32_C6_MINI_1N4/C5736265).

The MINI was checked independently against table 3-1 and the recommended land pattern in the [Espressif v1.5 manual](https://www.espressif.com/sites/default/files/documentation/esp32-c6-mini-1_mini-1u_datasheet_en.pdf), using 53 physical pin numbers and 61 native pad objects, including 9 ground pads that all belong to pin 49. The WROOM's 29-pin mapping cannot be reused. The MINI does not bring out GPIO10/11, so ARM changed to **GPIO14 / pin 19** and M0_BI to **GPIO23 / pin 29**; the firmware of that time was updated to match. The current firmware follows the new EasyEDA drawing: ARM is GPIO0 (pin 12), and GPIO14 is M2_FI.

2026-09 KiCad pins (superseded; now Motor1 22/23, 20/21, Motor2 14/7, 19/18, Motor3 1/6, 2/3):

| Physical motor | Top board → base board | FI / BI GPIO | Encoder A / B GPIO |
| --- | --- | --- | --- |
| Motor1 | M0 → H2 | 22 / 23 | 0 / 1 |
| Motor2 | M2 → H3 | 20 / 21 | 6 / 7 |
| Motor3 | M1 → H1 | 18 / 19 | 2 / 3 |

At that time UART TX16/RX17 mapped to module pins 31/30, and native USB GPIO12/13 were unused; now pins 31/30 are I2C_SCL (GPIO16) and IR_EN_N (GPIO17), and GPIO12/13 are the native USB console. The physical pins for GPIO4/5 sensing are 9/10. The GPIO15 pull-up and the encoder use of GPIO6/7 depend on the default JTAG selection and cannot cover arbitrary eFuse configurations. GPIO14 floats during chip reset, so an external 10k pull-down is added; this does not mean the actual motor power has been verified as off by default. [C6 chip datasheet](https://www.espressif.com/sites/default/files/documentation/esp32-c6_datasheet_en.pdf).

## Layout and interfaces

The PCB has two layers, 70 electrical footprints and 4 Ø2.4mm mounting holes, with **587 trace segments, 167 vias, two ground pours, 10 unconnected items**. Except for the four original base board mating headers, all electrical components are on the front. Placement coordinates come from the [hand placement table](../placement.json), and no autorouter was used; traces run in directions that are multiples of 30°. Ø6mm is currently reserved around the holes; the actual fasteners and top bracket are not verified.

The 19 pad centers, sizes, hole sizes, angles and through-hole attributes of the four connectors are identical, item by item, to the original top board. PWR was renamed PWR1: pin 1 GND, pins 2/3/4 VMOT. M0.1 is the controller 3.3V, M1.1/M2.1 are GND. After the base board CAD is rotated by about 30° and translated, the max residual of the 19 matching points is **0.00103mm**, with no mirroring; the top board outline is inside the base board. This is a nominal 2D dimension check, not a real tolerance or 3D mating verification.

The latest DRC keeps **one M2/PWR1 assembly boundary overlap**; it was not masked. The placed components report no copper short/clearance errors, but with only the local copper above, this cannot represent the whole board being connected. Adjacent pads of U4's fixed footprint are 0.15mm apart, using a 0.15mm rule that only applies to U4's internal pads; normal copper clearance stays 0.2mm, milled edge clearance 0.3mm, and the module's edge ground pads are locally 0.2mm. These are based on the 1oz two-layer process and cannot be applied directly to 2oz. [JLC capabilities](https://jlcpcb.com/capabilities/pcb-capabilities/).

Since the user allowed "the same shape as the base board", the top board now uses the nominal outline of the registered base board shrunk inward by 0.05mm, about 69.23 × 60.15mm; the original 19 pads, hole sizes and angles are kept. This is a CAD inset, not a guaranteed finished-dimension tolerance. USB moved 2.5mm toward the new bottom edge; the MINI moved up 3.84mm, and the decoupling capacitors and TX series resistor moved with it. The space and selection basis is in the [screening record](../outline_fit_review/README.md).

The MINI antenna end sticks out about **5.5mm** past the top board. The nominal 2D overlap of the native all-copper-layer keep-out with both the top and bottom boards is 0; the original position had about 61.37mm² of overlap with the base board. The [projection check](antenna_projection.json) measured only about **0.046mm** from the keep-out to the lower board outline, and about **0.204mm** from the nearest module pad to the top board edge. The former is less than normal milling tolerance; **zero nominal overlap still does not mean the actual RF clearance passes**; manufacturing tolerance, stack height, fasteners and communication tests still need verification. [Manufacturer module layout guide](https://docs.espressif.com/projects/esp-hardware-design-guidelines/en/latest/esp32c6/pcb-layout-design.html#general-principles-of-pcb-layout-for-modules-positioning-a-module-on-a-base-board).

The 3.3V power area re-placed C7/C8, the feedback R/C and the enable resistor, kept the two SW segments, redrew FB, and added input, output, enable and ground return copper. In the [local close-up](preview/u4_supply_detail.png), C8 sits near U4's input pin and C7 moved above the inductor to avoid the original M0 through-hole pads; the feedback node stays on U4's left, the separate output sense is taken from C11, and the feedback ground returns separately to U4's ground pin via. The right-side back ground pour gives the input and output capacitors a return path. Basis: [TI TPS563252 layout guide §8.4](https://www.ti.com/lit/ds/symlink/tps563252.pdf); this still needs real-board dynamic and thermal verification.

In the earlier 3.3V stage, the KiCad native copper connection graph checked six connection groups: VIN, GND, VOUT, SW, FB and EN; temporary copies with the input trace or the output trace cut both detected the expected break, and the unconnected count rose from 174 at the time to 175. [Original check record of that stage](../archive/u5_before_supply/top_board_v2_logic.verification.json). This 6V stage keeps all those traces and vias and re-checks the six connectivity groups. The input diode to this area was connected in the later input routing stage, and the rest of the circuit is still not fully routed; the 3.3V load distribution was connected in the later controller power stage; **partial connectivity does not mean the regulator or the whole board works**. Later loads must not connect to the thin separate output sense branch.

In the 6V area, L2 was rotated 90°, and C14–C19, the feedback R/C, the EN pull-down R24 and the bleed R30 were re-placed; no components were added. The [6V close-up](preview/u5_supply_detail.png) shows the input decoupling, BST/SW, soft start, feedback, output capacitors and bleed connections. R24 has moved near U5's EN, and the MCU-to-EN connection was made in the later control routing stage. The separate output sense and bleed branches each come out from the via at C19's output end; R30's branch does not connect at the feedback divider node. The layout follows [TI TPS62933 §12.1](https://www.ti.com/lit/ds/symlink/tps62933.pdf) to shorten the key pin paths; thermal and dynamic behavior with the current 1oz copper, the base board's large capacitors and the real load are not verified.

The USB interface finished this round's local hand routing: U2 was turned and moved close to the Type-C connector, the data lines pass through the protection pads, and the contacts for both plug orientations, the CC pull-downs, the USB-side VBUS and the decoupling connections were checked. 67 segments and 14 vias were added, with no new components. The [USB close-up](preview/usb_interface_detail.png) and the [full check notes](USB_ROUTING_REVIEW.md) record the locating hole avoidance, capacitor positions and unfinished conditions.

The [reset control area](preview/reset_control_detail.png), [controller EN/BOOT area](preview/mcu_reset_detail.png) and [full notes](RESET_ROUTING_REVIEW.md) record the specific connections and the remaining power conditions.

The controller power stage connected all 22 MAIN_3V3 net pads, including the controller, the VIO of the USB serial chip, the boot and encoder pull-ups, and the base board encoder power. C5/C6 form a local decoupling loop, and all 30 physical ground pads of the controller join the common ground; two BOOT segments made way for the short bridges where the power changes layers. The [controller power close-up](preview/mcu_supply_detail.png) and the [full notes for that round](MCU_SUPPLY_REVIEW.md) record the 66 new segments, 32 new vias and four component adjustments.

R25 moved near the controller and R20/R21 avoid the header holes and power capacitors; the schematic and BOM did not change. ## Verification and open items

The native netlist check covers all 246 physical pins, the 19 contacts, USB/EN/BOOT, the power sub-sheets and the manufacturer's module pads; all seven deliberately broken controls were detected. The original USB subcircuit's 72 DC and 3 timing simulations only cover that subcircuit, and the local RC simulation of the power supply is not a closed-loop regulator stability simulation either.

Added [24 DTR startup bias simulations](usb_startup_review/README.md): after the supply reaches 3.3V, the existing external pull-up keeps a sufficient model high level; a control with a wrong pull-down added detects insufficient margin; no parts were added as a result. The sampling instant, actual slow ramp/undervoltage and whole-board USB behavior are still not verified. The [wireless power policy](WIRELESS_POWER.md) is implemented: it starts wireless based on a valid voltage and auto-resets after power fails; the USB current budget and suspend current still need whole-board verification.

On 2026-09-09 the firmware **passed 73 offline checks and the two C6/R3 cross-compiles**; the logs and reports of that time have been overwritten by the current firmware verification, see git history and [FIRMWARE.md](FIRMWARE.md#verification). Motion is still forbidden by `BOARD_POWER_UNREVIEWED`; there has been no flashing, USB enumeration, wireless or loaded measurement.

The earlier ADC update only changed schematic comments and the implementation status and did not change the PCB at that time; see the [original comment version record](verification/adc_revision_evidence.json). The later U4 and U5 routing changed the PCB; the reports and previews of the earlier [7 copper segments](../archive/u4_before_supply/README.md) and [55 copper segments](../archive/u5_before_supply/README.md) are saved in historical checkpoints. To rebuild the schematic: run `python3 build_logic.py` and `python3 verify_logic.py` in the parent `controller_core`. The placement generator `build_placement.py` rebuilds the PCB and **must not be used to overwrite the existing hand-routed traces**. `route_local_power.py` and `verify_local_power_routes.py` only apply to the historical 7-copper-segment stage; this round's explicit coordinate plan is `route_logic_supply.py`, which only accepts the original 7-segment base and cannot simply be re-run to overwrite the current board.

The U5 hand coordinate plan `route_motor_supply.py` only accepts the old 55-copper-segment base; `route_usb_interface.py` only accepts the 103-segment base; `route_reset_control.py` only accepts the 170-segment base; `route_mcu_supply.py` only accepts the 255-segment base; `route_motor_controls.py` only accepts the 319-segment base; `route_encoder_links.py` only accepts the 375-segment base; `route_left_encoder_pair.py` only accepts the 422-segment base; `route_right_encoder_pair.py` only accepts the 456-segment base; `route_right_motor_pair.py` only accepts the 522-segment base; `route_vmot_distribution.py` only accepts the 554-segment base; `route_logic_input.py` only accepts the 566-segment base; none of them can be applied again to the current board. Verify the current local copper and the kept connections in the `controller_core` folder:

```sh
python3 verify_logic_input.py --board logic/top_board_v2_logic.kicad_pcb --baseline archive/logic_before_input/top_board_v2_logic.kicad_pcb
```

`verify_placement.py` uses KiCad's bundled Python to check the 2D interfaces and board outline; the project virtual environment runs `verify_antenna_projection.py` to check the antenna keep-out projection. `plot_placement.py` generates previews from the native KiCad layers, with an enlarged view to keep the antenna outline that sticks out past the board outline; the previews do not show ratsnest lines, so connectivity cannot be judged from the images. The checks do not access a real serial port or private config.
